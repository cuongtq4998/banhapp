# Admin Orders UI, part 5: S-A7 and S-A8, cakes (section 5)

Part of the split UI specification; index: [admin-orders-ui.md](../admin-orders-ui.md). [v1.1 | 2026-10-31] Form rules and shared state meanings: [part 4](04-screens-settings.md) and [part 2](02-screens-sign-in.md). The design board has no cake screens; these use the board's `ProductCard` list and form styles.

### S-A7 Cakes

- Purpose: see all cakes not removed; start add or edit (FR-21). Entry: S-A6 row. Exit: S-A8 (row for edit, add button for add).
- Layout: `TopBar` `A_ROW_CAKES` with `CountPill` `A_CAKES_COUNT` ("{n}/12 bánh"); `PrimaryButton` `A_ADD_CAKE` (full width under the title, plus icon); list of cake rows built like `ProductCard`: `size.thumb` image, name, price (`type.body.strong`), `StatusBadge` `A_CAKE_ACTIVE` or `A_CAKE_HIDDEN`; hidden rows dimmed to 70% but readable. Removed cakes are never listed (AC-34).
- Rules: at 12 cakes the add button is disabled and `NoticeText` `A_CAKES_FULL` explains why (AC-33); the server also refuses a 13th (`A_ERR_CAKES_FULL`). Order: active first, then hidden, each by name.
- States: Default; Loading (4 skeleton rows); Empty (cannot normally happen; `StateView` `A_CAKES_EMPTY` with `A_ADD_CAKE`); Error; Offline; Disabled (add button at 12); Success N/A. Image failed: `color.image.placeholder` with icon and label `A_IMG_FAILED_A11Y`.

### S-A8 Cake form (add and edit)

- Purpose: one form for a new cake and for changing an existing one; this replaces the two screens of v1.0 (FR-21, BR-12). Entry: `A_ADD_CAKE` (add mode) or a row on S-A7 (edit mode). [v1.1 | 2026-10-31]
- Layout, both modes: `TopBar` (add: `A_ADD_CAKE_TITLE`; edit: the cake name); picture area; `GlassCard` with `TextField` name (`A_F_CAKE_NAME`, 1 to 100), multiline description (`A_F_CAKE_DESC`, 1 to 300, counter), `TextField` price (`A_F_PRICE`, whole dong 1 to 100 000 000, suffix "đ"); `BottomActionBar`: add `A_ADD_CAKE_SAVE`, edit `A_SAVE`.
- Add mode: `ImagePickerField` (required) with the native photo picker (no permission prompt). The app checks before upload: JPEG or PNG up to 5 MB (BR-12); HEIC is converted to JPEG on the phone first (AC-33; TQ-D1). Other formats `A_ERR_IMG_TYPE`; larger `A_ERR_IMG_SIZE`; unreadable `A_ERR_IMG_READ`; the rejected picture is not kept. After a valid choice the preview shows with text buttons `A_IMG_CHANGE` and `A_IMG_REMOVE_PICK`. `NoticeText` `A_NEW_CAKE_ACTIVE`. Saving: the button shows `A_UPLOADING` with progress; the form is read-only; `SecondaryButton` `A_CANCEL_UPLOAD` stops it and nothing is created. Upload failure keeps all values and the picture and shows `InlineMessage` `A_ERR_UPLOAD`; retry through the same button; no cake exists until the whole save succeeds. Success: `Toast` `A_CAKE_ADDED`, back to S-A7 (new cake first in its group).
- Edit mode: read-only picture card (`size.imagePreview`, `radius.image`) with `NoticeText` `A_IMG_NOT_EDITABLE`; `ToggleRow` `A_CAKE_ACTIVE_TOGGLE` with helper `A_CAKE_HIDDEN_HELP`, saved with the form; `NoticeText` `A_NEW_ORDERS_ONLY` under the price; destructive `SecondaryButton` `A_REMOVE_CAKE`. Hiding or removing the only active cake is refused at once: the switch returns on with `Toast` `A_ERR_LAST_CAKE`, or the remove dialog is not opened (AC-32). Remove: `ConfirmDialog` (Destructive) `A_REMOVE_TITLE` naming `{name}`, body `A_REMOVE_BODY`, buttons `A_REMOVE_YES`, `A_BACK`; success `Toast` `A_CAKE_REMOVED`, back to S-A7 (AC-34).
- Validation (all at once, naming the field): no picture (add) `A_ERR_IMG_REQUIRED`; name empty or taken `A_ERR_CAKE_NAME_DUP`; price `A_ERR_RANGE_INT`; description `A_ERR_REQUIRED`/`A_ERR_TOO_LONG`; 13th cake `A_ERR_CAKES_FULL` as `InlineMessage` (AC-33).
- States: Default (add: empty form, Save disabled until all fields and a picture are set; edit: Save disabled until changed); Loading (edit: skeleton; add: upload progress); Empty N/A; Error (load: `StateView`; save: `InlineMessage`); Offline (`A_OFFLINE_SAVE`, form kept); Disabled (Save as above; remove while saving; the form while uploading); Success. Cake removed by another session: `StateView` `A_CAKE_GONE` with `A_BACK_TO_LIST`.
- Leaving with any value or picture shows the Dirty back dialog of part 2.
