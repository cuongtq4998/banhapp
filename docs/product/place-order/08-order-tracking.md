## 14.7 Security consequence of phone-only lookup (owner accepted the residual risks as written, 2026-11-02)

Residual risks accepted: anyone who knows a phone number can see that phone's orders; an attacker can use up a victim's per-phone lookup budget (the victim then phones the shop). Upgrade path if abused: the order code as a second field, or an SMS code (costs money, needs owner approval). [v1.11 | 2026-11-02]

A phone number alone is easy to guess or to know (neighbours, colleagues, an ex-partner, a scraped list). Anyone who knows a customer's number can see that customer's orders: cakes, prices, dates, status, district, masked phone. There is no second secret. The owner chose this for simplicity (Q-O6, Q-O10); it is recorded, not hidden. Required mitigations: lookups per hour limited per phone and per device or network address (BR-17, AC-44, AC-48); one answer shape for a phone with and without orders so the endpoint does not tell which numbers are customers (AC-48), noting that the list itself shows to a person who knows a right number; only the minimum data (BR-16, AC-47). Not decided, a later option if misuse appears: add the order code, or an SMS code, as a second secret (the code is free; SMS costs money and needs owner approval). [v1.10 | 2026-11-02]
