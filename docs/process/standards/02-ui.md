# Standard 02: Feature UI (`docs/design/<feature>-ui.md`)

Owner: `canvas-ui`. Readers: `atlas-architect`, `forge-dev`, `probe-qa`.

Purpose: specify how the interface behaves precisely enough that a developer builds it without guessing. No code, no business logic.

Input: the approved PRD. Record its version in `Based on`.

Update trigger: the PRD changes. Edit in place with labels.

## Required sections

| # | Section | Content |
| - | ------- | ------- |
| 1 | Header block | Includes `Based on: product/<feature>.md vX.Y` |
| 2 | Overview | Apps (Customer, Admin) and platforms (iOS, Android) covered |
| 3 | User Flow | Steps, entry and exit points, error branches (Mermaid `flowchart`) |
| 4 | Screen Inventory | `S-n`, name, app, purpose, FRs covered |
| 5 | Screen Specs | One subsection per screen (below) |
| 6 | Platform Notes | Only where iOS and Android differ, and the native technology used |
| 7 | Motion & Haptics | Transitions, feedback; only what a requirement or the native style calls for |
| 8 | Content & Copy | Key to text table (Vietnamese display text) |
| 9 | Accessibility | Labels, touch targets, contrast, dynamic type |
| 10 | Traceability | FR to screens matrix |
| 11 | Assets | Links to mockups or exported images (fake data only) |
| 12 | Open Questions / Change log | |

### Each screen spec contains

Purpose, Entry/Exit, Layout (regions top to bottom, component names from `design-system.md`), Data shown (business terms, not column names), Actions, **States** (Default, Loading, Empty, Error, Disabled, Success; "N/A" with a reason if not applicable), Validation (rule and message key).

## Rules

1. Every action on a screen traces to an FR. Elements without a trace are removed or raised as a question.
2. Do not invent business rules. Missing rule: raise it as a business question for `scribe-requirements`.
3. Use design-token names (`color.primary`), never raw values. Raw values live in `design-system.md`.
4. Display text is referenced by key; the text lives in Content & Copy.
5. Screen IDs are stable. No source code in the document.
6. Prefer native, current UI technology and research it before choosing: iOS Liquid Glass (iOS 26+, with a documented fallback for older systems), Android Material 3 Expressive. Cite sources. Choosing a minimum OS version is an architecture decision (ADR), not decided here.
7. The text specification is authoritative. A mockup is only a visual reference.

## Accessibility defaults

Touch target at least 44 pt (iOS) and 48 dp (Android). Text contrast at least 4.5:1. Every icon-only control has a label. Layout survives the largest dynamic text size.

## Ready gate (before `atlas-architect` and `forge-dev`)

- Every FR with UI impact appears in Traceability.
- Every screen has all six states or an "N/A" with reason.
- No blocking open question. Copy is final or marked pending with a question.

## Quality checklist

- A developer builds each screen without asking about layout or states.
- QA derives test cases from states and messages.
- iOS and Android are described once where identical.
